
### B. `prompts.ts` `l3`（指令 7）— 整段換成更新檔原文
變數只有標的（`${ctx.target}`）。與現況相比的差異：

**② CCC** 「這個成本是否超過預期報酬的 1/3？」→「這個成本是否超過預期報酬 **R** 的 1/3？」，並在「兩者的百分比差距」之後插入：
```
　【R 的來源寫死，不接受其他算法】
　 R ＝（基準目標價 V － 現價 P0）÷ 現價 P0
　 V ＝ 同子段同儕本益比中位數 × 預估 EPS 中位
　 ・同儕母體：交集卡聚焦子段內的同業，至少五檔。
　　 不足五檔必須揭露，並列出你採用了哪幾檔、
　　 每一檔的本益比與資料日期。
　　 本益比為負或查不到的成員不計入。
　 ・預估 EPS：至少兩個獨立來源（法說會指引、
　　 券商預估、公司財測），列出來源與日期。
　　 只有一個來源時明確標註「單一來源」。
　 ・自身歷史中位本益比只能當「悲觀防追價下限」，
　　 不可以當基準。
　 ・禁止直接引用券商目標價或媒體目標價當作 R。
　 ・請同時給三個情境：
　　 基準＝同儕中位本益比 × 預估 EPS 中位
　　 樂觀＝同儕中位本益比 × 預估 EPS 高值
　　 悲觀＝自身歷史中位本益比 × 預估 EPS 低值
　　 悲觀情境 R≤0 不構成否決，但必須在卡上揭露。
　 ・若同儕母體湊不出來，或預估 EPS 沒有來源 →
　　 R ＝未知。此時判「未知待核」，
　　 不是「通過」，也不是「不做」。

　【R 減半壓力測試】
　 把 R 砍一半（門檻變成 R/6）後，
　 確認成本是否仍在門檻內？
　 若砍半後超過，請在交棒卡註明「R 敏感」。
```

**④** 整段由「部位建議」換成：
```
④ 四態進場判定
　 只能輸出下列四態之一：可進場（現在）／
　 可進場（條件價）／可進場（條件事件）／不進場。
　 必須按下面的順序檢查，前面一條成立就停，
　 不要再往後找理由：
　 (1) 硬否決 → 不進場。只在條件「已知為真」時成立：
　　　 證偽已觸發、段位被替代或租金已消散、
　　　 R≤0、CRS 紅燈。
　 (2) 時機否決 → 條件事件。L4 生命週期極端、
　　　 租金高峰（原本沒有部位就不建新倉）、
　　　 CRS 橘燈停止加碼、只有落後層訊號、形成期。
　 (3) 價格否決 → 條件價。確認成本合計超過 R/3，
　　　 或價格不在價帶。必須附 P0 上限。
　 (4) 事件待確認 → 條件事件。確認價對應的基本面
　　　 條件還沒發生，或領先層觸發還沒出現。
　　　 寫明是哪一個事件、哪一天檢查。
　 (5) 必要輸入未知 → 條件事件 ＋ 待核清單。
　　　 未知不是通過。任一必要輸入缺席
　　　（例如 R 沒有錨），不得判「可進場（現在）」。
　 (6) 以上皆無 → 可進場（現在）。

　 價格再便宜也跳不過 (1) 與 (2)，那是紀律；
　 (3) 與 (4) 必須給出價位與日期，那是訊號。

　【P0 上限】把「太貴」反解成最高可接受買價：
　 P0* ＝ V ÷（1 ＋ 3×C）
　 V ＝基準目標價　C ＝確認條件成本（小數）
　 只在 C 隨現價等比移動時成立。若確認價是絕對價位
　（某條均線、某個財報對應價），這個閘門會變成
　 獎勵追價，P0 上限不適用，請明確註明。

　【部位形式】分批還是一次到位？規模上限？
　 若採分批，各段的觸發條件是什麼？
　 這一段只有判定為「可進場（現在）」時才需要回答。
```
