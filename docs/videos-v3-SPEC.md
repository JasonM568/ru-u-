# 課程影片 v3：以「課程」為單位開通

狀態：PRD v1.0（2026-10-03 定稿）｜決策者：Jason｜前置：影片 v2 已於 2026-10-03 上線（`videos-v2-SPEC.md`），本案將其「逐支開通」改為「逐課程開通」。

## Goal / Problem

影片 v2 的開通單位是「一支影片」：一期的兩天課程共 10 支，講師要逐支設定（或對 Day1、Day2 各套用一次）；學員進入後直接看到影片列表，沒有「課程」這一層。

Jason 的實際心智模型是：
- 一期的課程影片＝**一門課**（例：『2026 第一期菁英班課程影片』），內含 Day 1、Day 2 兩段。
- **開通＝勾選期別＋指定課程**，該課程 Day 1、Day 2 全部影片一次開通。
- 學員動線：課程列表 → 點課程名稱 → 看到 Day 1、Day 2 的課程列表 → 點影片播放。

## Users & Scenarios

- **管理員**：建立課程「2026 第一期菁英班課程影片」→ 把影片加入課程並指定分段（Day 1／Day 2）→ 試播後發布 → 課程「開通」勾選 2026 第 1 期 → 一期學員全部看得到。二期開課時另建「2026 第二期菁英班課程影片」開給二期；必要時把一期課程也開給二期當複習。
- **學員**：`/videos` 看到自己被開通的課程卡片 → 點進課程 → Day 1、Day 2 列表 → 播放頁。

## MVP Scope

**A. 課程與開通（2026-10-03 拍板）**
- 新增「課程」：名稱、說明（選填）。
- 影片**隸屬一門課程**，並指定分段。分段沿用固定四類：課前資料／Day 1／Day 2／補充教材，沒有影片的分段不顯示。
- **課程開通對象**：
  - **期別可複選**（一門課可同時開給多期）
  - **指定個人**（補課、旁聽，以整門課為單位），可「整批選取某期別／隊伍」展開為個人名單（快照）
- 開通後，該課程內**已發布**的影片全部對開通對象可見。

**B. 影片草稿（拍板：保留「先看過再開放」）**
- 影片加入課程後是**草稿**，只有講師看得到；講師試播後按「發布」，已開通此課程的學員即自動看得到。
- 可「取消發布」退回草稿。

**C. 學員動線（三層）**
1. `/videos`：課程列表（卡片：課程名稱、影片數）。只列自己被開通、且至少有一支已發布影片的課程。
2. 課程頁：依分段列出影片（Day 1 列表、Day 2 列表）。
3. 播放頁：沿用 v2 的播放器、章節側欄（**側欄只列同一門課的影片**）、上一集／下一集（**只在同一門課內**計算）。

**D. 沿用 v2（不重做）**
- 播放頁 fail-open：只有 oEmbed 明確 401／403 才蓋提示，其餘一律渲染 iframe；下方固定一行處理中說明；oEmbed 短期快取。
- 新增影片時 oEmbed 防呆擋私人影片。
- 寫入只走講師 RPC；RLS 為唯一權限邊界。

**E. 移除**
- v2 的「逐支開通對話框」與「套用到同分類」快捷——改由課程層級開通取代。
- v2 的 `video_audiences`（可見性改由課程開通決定，**仍維持單一可見性來源**）。

**F. 既有資料遷移**
- 建立課程「2026 第一期菁英班課程影片」，現有 10 支影片（Day 1 六支、Day 2 四支）全部歸入並維持「已發布」，課程開通給 2026 第 1 期。**一期學員無感。**

## Out of Scope

自訂分段名稱、課程封面圖、課程排序拖拉、觀看進度、留言問答、Vimeo 網域鎖定（列下期）。

## User Stories

1. 身為管理員，我勾選期別、指定課程，就能一次開通整門課的 Day 1、Day 2。
2. 身為管理員，我把晚幾天才上傳的 Day 2 錄影加入課程，試播後發布，已開通的學員自動看得到。
3. 身為管理員，我能把一期的課程也開給二期，或單獨開給補課學員。
4. 身為學員，我點課程名稱進去，看到 Day 1、Day 2 的課程列表，再點影片觀看。
5. 身為學員，我看不到沒開通給我的課程，以及課程裡還沒發布的影片。

## Acceptance Criteria

- **AC1** 課程開給期別 A：A 期學員在課程列表看得到、可進入、可播放已發布影片；B 期學員課程列表、課程頁、播放頁、API 皆看不到；直接打課程或影片網址得 404 或導回列表。
- **AC2** 權限由 **RLS 保證**：以 B 身分直查資料庫查不到該課程的影片。
- **AC3** 草稿：已開通課程內的草稿影片，任何學員皆看不到；講師看得到並標示「草稿」。發布後立即可見；取消發布立即消失。
- **AC4** 多期開通：課程開給一期＋二期，兩期皆可見；未開通的三期不可見。
- **AC5** 個人開通：課程開給二期學員 X，X 可見、二期其他人不可見。
- **AC6** 停權學員看不到任何課程與影片（含被個人開通者）。
- **AC7** 課程頁只顯示有影片的分段；播放頁側欄與上一集／下一集只在同一課程內、且只含有權看的影片。
- **AC8** 學員課程列表不顯示「已開通但沒有任何已發布影片」的課程（避免點進去空白）。
- **AC9** 手機版三層動線皆可用，播放器不溢出、側欄可收合。
- **AC10** **一期回歸**：上線前後一期 11 位學員可見影片集合逐人 0 diff（10 支），且課程列表恰好一門「2026 第一期菁英班課程影片」。

## Risks / Open Questions

- 🟠 **又一次可見性來源切換**：v2 剛上線的 `video_audiences` 要被課程開通取代。遷移必須比照 v2：交易式、guard、回滾守門、AC10 前後快照。
- 🟠 **影片移出課程／課程刪除**的行為要明確（建議：課程內有影片時不得刪除；影片換課程視同重新判定可見性）。
- 🔵 v2 的上線後待辦 🟡a（套用同分類並行一致性）隨該功能移除而失效。
- 🔵 `elite_videos_v2_backup` 的清除時機：v3 上線後一併評估。

## 下期待辦

- **影片編輯**（2026-10-03 獨立審查 🟡4）：目前標題、分段、說明填錯只能刪除重建，舊網址與發布狀態隨之失效。下期新增講師用的影片編輯 RPC（標題／分段／說明；換課程仍走移動流程並退回草稿）。
- `elite_videos_v2_backup`、`elite_videos_v3_backup` 的清除時機：v3 上線穩定 14 天後一併評估（drop 後對應的 down 不可再用）。

## Handoff Notes

**Backend（先提資料模型再動手）**
1. 候選：`elite.video_courses`（id、title、note、created_at）、`elite.course_grants`（course_id＋期別或個人二擇一，`on delete cascade`）、`course_videos.course_id`（FK）＋沿用 `published_at` 作為影片草稿／發布。
2. RLS：`is_enrolled() AND (is_instructor() OR (published_at IS NOT NULL AND 課程開通給 my_cohort() 或 auth.uid()))`；課程本身的可見性同理。
3. **硬性約束（前兩案的教訓）**：正式庫 `elite` default ACL 為 `authenticated=arwd`，每張新表先 revoke 再 grant，本機演練先重現此 ACL；新表自帶停權閘門；RLS 內呼叫的函式必須保留 authenticated EXECUTE；遷移由 PM 以 MCP `apply_migration` 執行。

**Frontend**
1. 三層動線：課程列表 → 課程頁 → 播放頁（沿用 v2 播放器與 fail-open）。
2. 講師後台：建立／編輯課程、課程開通對話框（期別複選＋指定個人＋整批選取）、影片加入課程並選分段、發布／取消發布。
3. 移除 v2 的逐支開通對話框與「套用到同分類」。

**QA**
1. AC1／AC2／AC3／AC5 以合成帳號實測，含直接打網址與直查資料庫。
2. AC10 一期回歸：遷移前後逐人快照。
3. 邊界：課程 0 支影片、課程只有草稿、學員 0 門課程（空狀態）、同一影片的上一集／下一集不跨課程。
