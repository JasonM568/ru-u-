## Goal / Problem

系統目前是**單期制**。`elite.enrollments.cohort` 欄位存在、NOT NULL、預設寫死 `'1.0'`，但沒有任何查詢或 RLS 用到它，後台也無處可設；現有 14 人（3 講師＋11 學員）全部掛 `'1.0'`。

11/7 第二期學員一被加進名冊，當下就會跨期看光：

| 資料 | 現行 SELECT | 第二期加入後 |
|---|---|---|
| 課程教材 `course_materials` | `is_enrolled()` | 🔴 看得到第一期全部教材 |
| 課程影片 `course_videos` | `is_enrolled()` | 🔴 由影片 v2 處理 |
| 團隊三表 `team_meetings`／`trade_ledger`／`reviews` | `team_id = my_team()` | 🔴 隊號沿用 1~N，兩期同隊號互看 |
| 作業流設定 `flow_configs` | `is_enrolled()` | 🟠 讀到第一期講師下發的設定 |
| 名冊 `enrollments` | 本人／同隊／講師 | 🟡 同隊號跨期混在一起 |
| 論點卡／對帳／作業存檔／問卷 | 本人＋講師 | ✅ 不受影響 |

目標：讓「期別」成為全系統的一等維度，第二期學員只看得到屬於自己那期的東西。

> **修正先前說法**：此案的修法不是把 `is_enrolled()` 改成同期判定（它的語意是「我在名冊內」，且被多張表的 INSERT 政策共用，改它會波及過廣）。正確做法是**內容資料本身要帶期別**，RLS 比對新函式 `elite.my_cohort()`。

## Users & Scenarios

- **管理員**：11 月開第二期 → 在後台新增期別 `2026-2` 並設為「當期」→ 把新報名的會員加進名冊（自動落在當期）→ 第一期學員維持 `2026-1`，雙方互不干擾。
- **學員**：登入後只看得到自己那期的教材、影片、團隊紀錄；完全無感，不需要選期別。

## MVP Scope

1. **期別主檔**：新增 `elite.cohorts`（`code` 如 `2026-1`、`display_name`「2026 第 1 期」、`started_on`、`is_current`）。管理員可新增期別、切換當期；同時只有一個當期。
2. **名冊管理期別**：`/admin/roster` 顯示並可修改每人的期別；新加入成員**預設落在當期**（取代現行寫死的 `'1.0'`）。
3. **內容掛期別**：`course_materials`、**`course_videos`**、`flow_configs`、團隊三表加上期別歸屬，RLS 改為比對 `elite.my_cohort()`。教材與影片皆加 `all_cohorts` 布林（多期通用，供課前資料這類內容使用）。
   - ⚠ **影片只做「期別隔離」這一半**（2026-10-02 修正）。原規格把影片整案推到 video v2，但 AC3 要求影片也不可跨期，兩者矛盾——此處為修正。逐影片開通、可看對象勾選、獨立播放頁、章節側欄仍屬 video v2。現有影片一律歸 `2026-1`（2026-10-03 正式庫實查為 **10 支**，非原估 4 支）。
4. **資料遷移**：既有 14 人 `'1.0'` → `2026-1`；既有教材與團隊三表一律歸 `2026-1`；`enrollments.cohort` 的 `'1.0'` 預設值移除，改由當期決定。
5. **講師跨期**：講師（`class_role='instructor'`）不受期別限制，看得到所有期別。
6. **學員停權（2026-10-02 加入）**：`enrollments` 加 `status`（`active`｜`suspended`）。停權者**保留名冊與既有紀錄**（問卷、論點卡、團隊紀錄不變成孤兒），但擋掉所有觀看與寫入；管理員可在 `/admin/roster` 切換，隨時可復權。用於退費、未繳費。
   - 實作：`elite.is_enrolled()` 改為 `... and status = 'active'`。**這是本案唯一該改 `is_enrolled()` 的地方**——它的語意是「我是有效名冊成員」，停權者本就不該讀也不該寫，故 SELECT 與 INSERT 政策同時收斂是正確的，與「不要把它改成期別判定」不衝突。
   - 停權者登入導向說明頁（比照既有 `/not-enrolled` 的做法），不是空白儀表板。

## Out of Scope

學員同時隸屬多期、期別結業／封存狀態、跨期數據比較報表、期別層級的首頁客製、自動依報名日期分期。
**特例跨期開通（補課／旁聽）本期不做**（2026-10-02 拍板）：先用人工處理——把該學員暫時改到另一期——等累積實際案例再評估。
**「某學員實際看得到什麼」的檢視畫面**本期不做。

## User Stories

1. 身為管理員，我要新增「2026 第 2 期」並設為當期，之後加入的會員自動落在這期。
2. 身為管理員，我要能把加錯期別的人改到正確期別。
3. 身為管理員，我要讓某些通用教材同時開放給多期。
4. 身為第二期學員，我不該看到第一期的教材、影片與團隊紀錄。
5. 身為講師，我要看得到所有期別的資料，不受限制。
6. 身為管理員，學員退費時我要停權他但保留他的紀錄，不用把人整個移出名冊。
7. 身為被停權的學員，我登入後應看到清楚的說明，而不是一片空白或錯誤畫面。

## Acceptance Criteria

- AC1 既有 14 人遷移後期別皆為 `2026-1`，登入後看到的內容與遷移前完全一致（無回歸）。
- AC2 新增 `2026-2` 並設為當期後，從名冊新增的成員期別自動為 `2026-2`。
- AC3 第二期學員登入：教材、影片、作業流設定、團隊三表皆**查不到**第一期資料；以其身分直查資料庫同樣查不到（RLS 層保證，非前端隱藏）。
- AC4 第二期與第一期存在同樣隊號（例如都有 A 隊）時，兩邊的例會／台帳／覆盤互不可見。
- AC5 講師帳號可見所有期別資料。
- AC6 同時只能有一個 `is_current`；切換當期為原子操作，不會出現零個或兩個當期。
- AC7 標記為「多期通用」的教材，兩期學員皆可見。
- AC7b **Storage 層同樣隔離**（2026-10-03 新增）：二期身分呼叫 `storage.from('elite-materials').list()` 看不到任何一期檔名；對已知一期路徑 `createSignedUrl` 失敗；一期學員與講師照常。
  - 背景：原 `elite_materials_storage_select` 只判 `is_enrolled()`，且同時管 list——資料表層隔離了，二期學員仍可從 Storage 列出全部檔名再簽發下載連結。此為獨立遷移檔，與主遷移分開執行。
- AC8 停權學員：所有頁面皆不可讀、不可寫（RLS 層保證），登入後看到說明頁；其既有問卷、論點卡、團隊紀錄**不被刪除**，講師後台仍查得到。
  - 停權即時性以「不再核發新的 signed URL」為準。教材的 signed URL 現行 TTL 1 小時，已核發者在到期前仍可用，故停權生效最長延遲 1 小時——**已知限制，接受不另做即時撤銷**（退費情境不需秒級對抗，為此多做一套會增加 10/23 前的風險）。
- AC9 停權後復權，該學員所見內容與停權前一致。

## Risks / Open Questions

- 🔴 **這不是純新增的 schema 變更**，會動到既有 RLS 與既有資料，與本專案過去「直打正式庫、純新增」的慣例不同。請 Tech Lead 先提出回滾方式再動手；建議在 Supabase branch 上先演練一次遷移。
- 🟠 **團隊三表掛期別的做法有兩個候選**，請 Tech Lead 擇一：(a) 三表各加 `cohort` 欄位，政策加 `AND cohort = my_cohort()`；(b) 改用全域唯一的 team 主檔（`teams(id, cohort, name)`），`my_team()` 回傳全域 id。(b) 較乾淨但改動面大，需評估 `/admin/teams` 既有程式。
- 🟡 教材的「多期通用」要做成期別多選，或只是一個「全期可見」布林值？建議先做布林值，不夠用再升級。
- 🟡 第二期開課前的空窗期：`2026-2` 已建立但尚未開課時，先加進去的學員會看到什麼？建議該期無內容即顯示空狀態，不報錯。
