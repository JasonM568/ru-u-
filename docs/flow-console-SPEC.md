```bash
npm run flow
```

起 dev server 並自動開 `http://localhost:3000/flow`。需要先登入（沿用 QBC 帳號），未登入會被導到 `/login`。

> 註：這個指令寫死 3000 埠。若 3000 已被占用，Next 會改用 3001，瀏覽器就會開錯頁——這時直接用 `npm run dev`，看終端機印出的實際埠號再手動開 `/flow`。


## 這是什麼

8/30 月例會教的「AI 供應鏈五層作業流」的線上版。

五個 skill（MacroScope／InPoMa／PROCapital／ChartScope／InDay）原本都是**單股縱向**設計。這套流程教的是把它們**橫向鋪在一條產業鏈上**：先掃完一層，再往下鑽一層。每層跑完產出一張「交棒卡」，往下傳的永遠只有交棒卡，不是整份報告。

控制台做的事：輸入股票代號 → 自動反查所屬子段、補齊同段與鄰段名單 → 依序產出八道指令 → 交棒卡貼回頁面後自動帶進下游指令 → 三道硬閘門攔截 → 收斂成一張投資論點卡。

**流程本質是「段」導向的**：L0 到交集都在做子段之間的橫向比較，需要一整段的同業清單，不是單一個股。輸入代號只是從流程中段切入的入口。

### 三道硬閘門（UI 會實際擋人，不只是提示）

1. **交集卡未填完 → 不准進 L3。** 只有一個證據就下注，是這套流程要防的第一件事。
2. **L3 的 CCC 確認成本 > 預期報酬 1/3 → 不必跑 L4，回頭換標的。**
3. **L3＋L4 合計確認成本 > 預期報酬 1/3 → 本案不成立。** 不管公司多好、價格多便宜。

合計規則兩種：**取較高者**（兩條件會被同一次上漲同時滿足）或**相加**（先後獨立的兩道關卡）。控制台可切換，切換會反映到論點卡起草指令。**全隊必須一致**，否則跨組比較沒有意義——同一組數字（100/105/108/0.35）取較高者是 22.9% 通過，相加是 37.1% 不成立。

## 資料出處與可信度（最重要的一節）

`lib/flow/segments.ts` 裡的個股分兩種，**程式與介面都必須分得清楚**：

| | 來源 | 標記 | 段位先驗 | 可信度 |
|---|---|---|---|---|
| 教材原表 | 《AI 供應鏈投資判斷一覽表(Elite)》 | 無 | 顧老師的判斷 | 以教材為準 |
| 補充個股 | Claude 依訓練資料（知識截止 2026-05） | `added: true` | **一律「未定」** | **尚未查證** |

- 教材原表：**74 個不重複代號、77 列**。台積電(2330)、群聯(8299)、臻鼎-KY(4958) 各被刻意放進兩個分類。
- 補充 16 檔：散熱 +5、CPO 與矽光子 +5、PCB +6。
- 介面上補充個股是虛線外框＋「補」標籤，滑鼠移上去顯示「非教材原表，需自行查證」，名單區有出處說明，並有「只用教材原表」開關可一鍵排除（會同步從所有指令中移除）。
- **段位先驗是老師的判斷，不代填。** 補充個股一律「未定」，等學員在 L2 用當期財報驗證後自己歸類。這也符合一覽表原本的設計：D 欄先驗只是起點，E 欄要自己填。

## 不可擅改

1. **指令文字是教材原文。** `lib/flow/prompts.ts` 裡的字串一字不改沿用《指令串 v2》，只代入四種變數（產業鏈名稱／個股清單／子段名稱／交棒卡）。改動指令文字＝改動教材，**先問講師**。
   - 特別是這幾句刪不得：L1 的「不是逐檔個股報告」（把 InPoMa 從縱向扳成橫向的關鍵）、L2 的「不要提任何籌碼資訊」（交集的前提）、論點卡起草的「第七欄我自己寫，你不要幫我寫」。
2. **不要把補充個股的段位填上去。** 那是老師的判斷。
3. **不要幫跨原分類的自訂子段編一個門檻。** 目前行為是明說「沒有單一門檻可用，請自己訂或再拆細」——那個誠實的空白就是資訊。
4. **不要把八道指令接上 AI API 自動執行。** 教材刻意要求「每層開新對話」以免 skill 互相干擾、偏誤累積。自動化掉就毀了方法論。
5. **CCC 之後上雲時，server action 必須用 `lib/flow/ccc.ts` 重算**，不信任前端傳來的數字。比照 `lib/scoring.ts` 的既有做法。

## 目前狀態與後續三階段

**階段一（已完成，未合併）**：控制台移植進站，資料存 localStorage（key = `flow5:{userId}`，帶 user_id 所以同一台電腦多人登入不會互蓋）。

**階段二　論點卡上雲**
- 新表 `elite.thesis_cards`（MCP `apply_migration`，name `elite_thesis_cards`）
- RLS：學員讀寫自己（`user_id = auth.uid() and elite.is_enrolled()`）；講師 select 全部（`elite.is_instructor()`），**講師不能改學員的卡**
- `app/(app)/flow/actions.ts` 的 `saveThesisCard`：比照問卷，狀態序列化進 hidden field → server 端 `JSON.parse` → **用 `lib/flow/ccc.ts` 重算 cc_* 五個欄位**後才寫入
- `app/(app)/flow/cards/page.tsx` 我的論點卡列表

**階段三　講師端與 T+20 對帳**
- 新表 `elite.thesis_reconciliations`
- `lib/flow/reconcile.ts` 四象限判定純函式（server 端重算）：未觸發＋賺＝論點成立｜未觸發＋賠＝證偽條件設計失敗（重寫條件，不是換標的）｜觸發＋執行＝紀律及格｜觸發＋未執行＝紀律失誤（最嚴重）
- `app/(app)/admin/thesis-cards/page.tsx`：比照 `admin/teams/page.tsx`，平行 select ＋ JS 端 Map join 出 display_name

**階段四　分段設定由講師下發**
- 新表 `elite.flow_configs`，講師寫、名冊內學員讀
- 目前的替代做法：控制台已有「匯出／匯入分段設定」（一串 JSON，約 700 字），零後端也能讓全班統一

### 動資料庫前的鐵則

- **只在 `elite` schema 建表，永不碰 `public`**（共用 QBC 正式庫，239 會員真實資料）
- migration 前先 `list_tables` 確認同名表不存在
- **RLS 是安全邊界**，每張表都要雙向實測：本人看得到、他人 0 筆
- 不用 service role key

## 驗收清單（UAT）

Claude 不能輸入密碼，無法代測登入後的流程。以下要人工走：

**學員（用「學院測試」登入）**
1. 導覽列點「作業流控制台」→ 頁面正常載入
2. 輸入 `1519` → 比較群組自動變「電源供應」、13 檔、候選標的顯示「1519 華城　瓶頸段先驗」
3. 展開「L1 前置：籌碼蒐集」→ 指令裡的名單是那 13 檔 → 按「複製指令」可貼出
4. 在 L0 貼一張假交棒卡 → 展開 L1 → 指令開頭已帶入該內容，佔位符消失
5. 交集站硬閘門選「尚未填完」→ 出現紅色警示、左側狀態變「閘門未過」
6. 論點卡填 100 / 105 / 108 / 0.35 → 顯示 5.0% / 8.0% / 8.0% / 22.9% / 通過
7. 預期報酬改 0.15 → 53.3% / 本案不成立 + 紅色警示
8. 按「自訂分段」→ 新增子段 → 把兩檔搬進去 → 指令名單與 L1 的 SLT 分級行跟著變
9. 輸入 `2603`（不在清單）→ 跳紅色警示，明說「指令跟你輸入的代號沒有關係」
10. 手機寬度檢查
11. 「匯出作業紀錄」可複製出完整 Markdown

**講師**：導覽列同樣看得到，功能一致（本階段沒有講師專屬功能）。
